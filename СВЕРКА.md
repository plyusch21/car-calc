## Расхождения — разбор

### Р-1. Шапки карточек сделаны только в `index.html`

**Просил** (Блок 1): «Рабочие карточки (Автозаполнение, Параметры авто, Доп. данные, Таможенные платежи, Доставка, Комиссии, все карточки настроек)» — перечислены только карточки калькулятора.

**В коде:** `index.html:79-89` — шапка по спецификации, `.receipt-title` для чека `index.html:85`, применена на `:1621`. `deals.html:41` — `.card h2` остался старым: 13px, серый, по левому краю, без подложки. На странице сделок 10 карточек с `<h2>`.

**Почему разошлось:** я сформулировал двусмысленно — перечислил карточки одного файла, про `deals.html` не сказал ни слова. Claude Code сделал ровно то, что написано.

**Приоритет:** 4 — косметика, но при переходе между разделами заметно.

### Р-2. Шапка страницы оставлена пустой

**Просил** (Блок 2): «На её место — название `BAIKAL AUTO` слева и текущее направление справа (`Япония 🇯🇵`)».

**В коде:** `index.html:280` — `<div class="topbar"></div>`, пустой. Комментарий `index.html:52-54`: «раньше тут был текст "BAIKAL AUTO" + направление, убраны как дублирующие вкладки направлений/истории, которые и так показывают то же самое». Коммит `7639861` («redundant topbar»).

**Почему разошлось:** Claude Code сначала сделал как просили, потом на живом устройстве решил, что направление дублирует вкладку под шапкой, и убрал. Осознанное решение, не misread. Название компании при этом тоже ушло.

**Приоритет:** 4.

### Р-3. Текст про обновление курсов снова не соответствует реальности

**Просил** (Блок 2): «после Блока 8 — "Обновляется дважды в сутки и при открытии приложения"». Это предписание исходило из Блока 8, где сторож планировался на `0 0,12 * * *`.

**В коде:** текст стоит — `index.html:1095` и `:2710`. Но `vercel.json` содержит `"schedule": "0 0 * * *"` — **раз в сутки**. Коммит `f849365`: «Fix rates-refresh cron: once daily, not twice — Hobby-plan limit broke routing». Комментарий в `api/rates-refresh.js:4` («0:00 и 12:00 МСК») тоже устарел.

**Почему разошлось:** внешнее условие — бесплатный тариф Vercel не даёт крон чаще раза в сутки. Крон урезали, а текст в интерфейсе, выведенный из старого крона, не пересмотрели. Это ровно та ситуация, которую Блок 2 чинил: интерфейс обещает то, чего нет.

**Приоритет:** 3 — сейчас рядом стоит живой индикатор «обновлён / не обновился», так что реальный статус виден, но текст врёт.

### Р-4. Архив хранится одним ключом на всех пользователей

**Просил** (Блок 3): «Архив хранить отдельным ключом, не внутри `state:history`». (Блок 9): «Разнести по пользователям: `state:history:<uid>`».

**В коде:** `api/state.js:13-15` — `"state:archive" (JSON array, capped at 50 — still shared … only asked to split "history", not "archive")`. Чтение `:49`, запись `:110`. История разнесена (`state:history:<uid>`, `:45`), архив — нет.

**Почему разошлось:** моя недосказанность. Блок 9 говорил про историю, про архив не сказал. Claude Code это заметил и написал в комментарии, но не расширил. У архива тот же класс проблемы, что был у истории: два менеджера будут затирать его друг другу.

**Приоритет:** 2 — пока пользователь один, невидимо; с появлением второго менеджера проявится сразу.

### Р-5. Тумблер «каталожная стоимость» не сбрасывает таможню

**Просил** (Блок 4): список полей, сбрасывающих таможню: «`carPrice`, `extraCosts`, `volumeCm3`, `power`, `powerUnit`, `engineType`, `age`, `customsValueManual`, `eaeuFullDuty`».

**В коде:** все девять покрыты — `index.html:1452` (`CUSTOMS_AFFECTING`), `:1480-1489`. Но сам тумблер `customsValueOverrideToggle` (`index.html:1490`) только перерисовывает форму и таможню не сбрасывает.

Сценарий: посчитали с включённой каталожной стоимостью → выключили тумблер → нажали «Отправить». В TKS уходила каталожная стоимость, в КП уйдёт таможня от неё, а цена — фактическая. Обычно каталожная выше фактической, так что клиент получит **завышенную** пошлину.

**Почему разошлось:** я перечислил значение (`customsValueManual`), но не тумблер, который решает, использовать ли его.

**Приоритет:** 1 по шкале — сумма в КП неверная. Сценарий редкий и завышает, а не занижает, но по формальному критерию — критично.

### Р-6. Сторож курсов работает раз в сутки

**Просил** (Блок 8): «`"crons": [{ "path": "/api/rates-refresh", "schedule": "0 0,12 * * *" }]`».

**В коде:** `vercel.json` — `"0 0 * * *"`. Дополнительно появился `"/api/deals-cleanup"` на `30 0 * * *` (вне задания).

**Почему разошлось:** лимит бесплатного тарифа Vercel (Hobby): крон не чаще раза в сутки. См. Р-3.

**Приоритет:** 3.

### Р-7. Разбор курсов ATB/Naver остался привязан к вёрстке

**Просил** (Блок 8): «искать не по цепочке "блок с классом → отрезок 6000 символов → подстрока", а по смыслу — все числа рядом с "JPY"/"йена" во всём документе, и брать единственное, попадающее в коридор».

**В коде:** `api/rates.js:169-185` (`getJpy`) — цепочка сохранена: `id="currencyTab4"` → `currency-tabs__item` → `>JPY<` → `продажа`, и только на последнем шаге число выбирается по коридору 30–90 (`pickInCorridor`, `:152`). Смена id или класса на atb.su по-прежнему ломает разбор.

Комментарий `api/rates.js:128-136` объясняет: поиск по всему документу давал несколько правдоподобных чисел (другие тарифы, другие вкладки), живой тест обеих функций показал, что «самое частое» — ненадёжно. Оставили цепочку + коридор как компромисс.

**Почему разошлось:** осознанный компромисс по результатам живого теста, не misread. Молчаливая поломка теперь закрыта сторожем (Р-6) и красным статусом в виджете — то есть цель Блока 8 достигнута другим путём.

**Приоритет:** 3.

### Р-8. HTTP-коды: «нет доступа к сделке» отдаёт 400

**Просил** (Блок 9): «401 — доступ; 400 — неверный запрос; 502 — внешний сервис; 500 — своя ошибка».

И в `api/parse-listing.js:1291` остался один ответ `200` с полем `error`.

**Почему разошлось:** в ТЗ не было кода 403 — я дал четыре кода, и «нельзя эту сделку» ни под один не подошёл. Claude Code взял ближайший.

**Приоритет:** 4 — на работу не влияет; влияет только на то, как ошибки выглядят в панели Vercel.
