## Блок 2. Блок курса на экране расчёта

### Что убрать

- Строку с датой из верхней части страницы (`#dateLine`). На её место — название `BAIKAL AUTO` слева и текущее направление справа (`Япония 🇯🇵`).
- Текст «Автообновление 2 раза в сутки» в настройках и в редакторе курса — это неправда, расписания нет. Написать «Обновляется при открытии приложения», а после Блока 8 — «Обновляется дважды в сутки и при открытии приложения».

### Что добавить

Новый блок **над карточкой автозаполнения**, на каждом экране расчёта:

```
┌──────────────────────────────────────┐
│      понедельник, 15 сентября 2026   │   ← по центру, 11.5px, var(--muted)
│  ● обновлён     0,5730    ЙЕНА / ₽   │
└──────────────────────────────────────┘
```

Вторая строка — сетка `grid-template-columns: 1fr auto 1fr`:

- **слева** статус: кружок 8px + слово, 12.5px;
- **по центру** значение: `IBM Plex Mono`, 15px, `font-weight:600`, `font-variant-numeric: tabular-nums`;
- **справа** название пары: 12px, `var(--muted)`, выравнивание по правому краю.

Значение обязано стоять в отдельной центральной колонке, чтобы не смещаться при разной длине статуса.

**Статусы:**

| Состояние | Цвет | Слово |
|---|---|---|
| Обновился сегодня и прошёл проверки Блока 8 | `var(--teal)` | обновлён |
| Не удалось обновить, или значение не прошло проверку, или курс не менялся 3 дня | `var(--danger)` | не обновился |

Нажатие на блок открывает историю этого курса (Блок 8).

**Какой курс показывать по направлениям:**

| Направление | Пара | Значение |
|---|---|---|
| Япония | ЙЕНА / ₽ | `CONFIG.rates.JPY.value` |
| Китай | ЮАНЬ / ₽ | `CONFIG.rates.CNY.value` |
| ЕАЭС | USDT / ₽ | `CONFIG.rates.USDT_RUB.value` |
| Корея | ВОНА / ₽ | `USDT_RUB.value / KRW_USDT.value` — расчётный курс, тот же, что участвует в расчёте |

Для Кореи статус — худший из двух исходных курсов.

## Блок 3. Сброс формы и архив расчётов

### Новое правило сброса

После **отправки** или **сохранения в историю** очищается всё, **кроме**: объём двигателя, мощность и её единицы, тип двигателя, возраст автомобиля, привод, трансмиссия.

Очищаются: марка/модель, цена, расходы в стране, комплектация, пробег, дата выпуска, состояние, примечания, текст объявления, посчитанная таможня.

Перенесённые поля подсветить: под полем серым 10.5px «перенесено из прошлого расчёта». Подпись снимается, как только поле изменили вручную или перезаписало распознавание.

### Автозаполнение перезаписывает всё

Сейчас в `runListingParse` распознанное подставляется только в пустые поля (проверка `isEmpty`). **Убрать эту проверку** — распознанное значение всегда побеждает.

### Подсветка незаполненных полей

После распознавания поля, которые остались пустыми, получают:

```css
border-color: #d9b25f;
border-style: dashed;
```

и подпись под блоком: «Объём не указан в объявлении — впишите вручную» (цвет `#d9b25f`, 10.5px). Подсветка снимается при вводе.

### Архив на 50 расчётов

Во вкладке «История» → «Общие» добавить папку **«Архив»**.

- Туда **автоматически** попадает каждый расчёт, доведённый до результата, — нажимать ничего не надо.
- Хранятся последние 50, более старые стираются молча.
- Кнопка «Сохранить в историю» остаётся как есть и служит для постоянного хранения.
- Архив хранить отдельным ключом, не внутри `state:history`.

## Блок 4. Таможня — защита от неверной цены клиенту

### Сброс посчитанной таможни

Любое изменение поля из карточки «Параметры авто», **кроме марки/модели**, обнуляет `f.customsAuto` и прячет блок результата. Список полей: `carPrice`, `extraCosts`, `volumeCm3`, `power`, `powerUnit`, `engineType`, `age`, `customsValueManual`, `eaeuFullDuty`.

**Если включён тумблер «Указать вручную» — не трогать ничего.** Там значение владельца.

### Не показывать результат без таможни

Если ручной ввод выключен, а `f.customsAuto` пуст (TKS и alta.ru оба не ответили), `showResult` не рисует чек. Вместо него плашка `.notice`:

> Таможенные платежи не рассчитаны. Нажмите «Рассчитать» ещё раз или включите «Указать вручную».

Сейчас пустое значение превращается в ноль, и клиенту уходит КП, заниженное на сумму пошлины.

## Блок 7. Закрыть открытые адреса

Четыре эндпоинта не проверяют, кто пришёл. Посторонний, знающий адрес приложения, может жечь платный ключ TKS и бесплатную квоту Gemini, а занимая распределённую блокировку `tks:ratelimit`, ронять расчёт у владельца.

Добавить в начало обработчика, после разбора `body`:

```js
const { authenticate } = require('./_lib/access');
const auth = await authenticate(body.initData);
if (!auth.ok || auth.record.status !== 'approved') {
  res.status(401).send(JSON.stringify({ error: auth.ok ? 'доступ не подтверждён' : auth.error }));
  return;
}
```

В：

- `api/customs.js` — весь обработчик;
- `api/parse-listing.js` — весь обработчик, включая режим `debugFreeform`, который вдобавок разрешить только владельцу (`auth.record.isOwner`);
- `api/share-relay.js` — только ветку `action === 'put'`. Ветку `get` оставить открытой: её вызывает страница во внешнем браузере, где `initData` нет, а id из 12 случайных байт не подобрать и читается он один раз.

На клиенте добавить `initData: getInitData()` в тела запросов `fetchCustomsQuote` и `runListingParse` (в `share-relay` он уже передаётся).

**Последствие:** кнопки распознавания на странице `/diag` перестанут работать без Telegram. Так и должно быть — это было окно для посторонних. Сообщи об этом владельцу.

`api/rates.js` можно оставить открытым, но добавить кеш ответа в KV на 10 минут, чтобы не ходить на банковские сайты при каждом запросе.

## Блок 8. Курсы — защита от молчаливой поломки

Курсы йены и воны берутся разбором HTML чужих сайтов по цепочке привязок к вёрстке. Когда вёрстка меняется, разбор ломается, а приложение молча продолжает показывать старое значение — красная строка видна только в настройках, куда владелец заходит редко.

Источники менять **не нужно**, нужны именно эти. Задача — чтобы поломка была заметна в тот же день.

### История курсов

Каждое успешное обновление записывать: валюта, сырое значение, итоговое с корректировкой, источник, время. Хранить **3 месяца**, отдельным ключом в KV — **не внутри `state:config`**, он и так общий и тяжёлый.

Показывать в настройках, подразделом внутри «Курсы валют». Нажатие на блок курса на экране расчёта открывает историю этой валюты.

### Три проверки перед применением значения

1. **Коридор правдоподобия.** Йена 0,3–0,9 ₽; юань 8–20 ₽; USDT/вона 1000–2000; USDT/₽ 50–200. Значение вне коридора не применяется, курс помечается красным.
2. **Скачок.** Разница с предыдущим значением больше 15% — не применять молча, пометить красным и показать оба значения.
3. **Застой.** Значение не менялось 3 дня подряд — почти наверняка разбор сломан и отдаёт старое. Пометить красным.

### Устойчивый разбор

Переписать `getJpy` и `getUsdtKrw` в `api/rates.js`: искать не по цепочке «блок с классом → отрезок 6000 символов → подстрока», а по смыслу — все числа рядом с «JPY»/«йена» (или `원`/«USDT») во всём документе, и брать единственное, попадающее в коридор правдоподобия. Такой разбор переживает перестановку блоков и смену классов.

### Ежедневный сторож

`vercel.json` → `"crons": [{ "path": "/api/rates-refresh", "schedule": "0 0,12 * * *" }]`.

Новый эндпоинт: обновляет курсы, кладёт в KV, сверяет с курсом ЦБ (он доступен всегда) и при расхождении или непройденной проверке шлёт владельцу сообщение в Telegram через Bot API — токен уже есть в `process.env.TELEGRAM_BOT_TOKEN`.

### Курсы ЦБ справочно

В настройках, в разделе «Курсы валют», подблок **«Курсы ЦБ»**: доллар, юань, йена, вона, евро. Только для справки, в расчёте не участвуют.

**Не забыть номинал:** у ЦБ йена котируется за 100 единиц, вона за 1000. Делить на `Nominal` — готовая логика есть в `cbrRateToRub` в `api/customs.js`.

Евро сейчас тянется при каждом входе, но в расчёте не участвует вообще (пошлину считает TKS). Перенести его в этот же подблок.

## Блок 9. Данные и доступ

### История расчётов по пользователям

`api/state.js` пишет в единственный ключ `state:history` — один на всех. Двое работающих одновременно молча затирают историю друг другу: кто сохранил последним, тот и прав.

Разнести по пользователям: `state:history:<uid>`. **Сделать до появления второго менеджера.**

### Настройки — защита от затирания

`state:config` остаётся общим (это настройки организации), но добавить версию: при сохранении сервер проверяет, что версия совпадает с прочитанной. Не совпала — не затирать, вернуть ошибку и сообщить.

### Права на контрагентов

В `api/deals.js` действия `saveParty`, `getParty`, `findPartyByPhone` и список `parties` в `bootstrap` не проверяют уровень доступа — в отличие от сделок. Менеджер с уровнем «только свои» видит и правит всю базу контрагентов, включая условия работы дилеров.

- `saveParty` для существующего контрагента — только `full` и владелец.
- `parties` в `bootstrap` и `getParty` — фильтровать по правам.
- `findPartyByPhone` при отсутствии прав на запись — отдавать только `{found:true, name}`.

### Ошибки с правильными кодами

Сейчас все эндпоинты отдают ошибки с HTTP 200 и полем `error` в теле. В панели Vercel ровная зелёная линия, даже когда приложение не работает.

- 401 — доступ;
- 400 — неверный запрос;
- 502 — внешний сервис (TKS, alta.ru, Gemini, банки);
- 500 — своя ошибка.

Плюс `console.error` с телом ответа во всех `catch` серверных функций — Vercel их собирает.

## Блок 10. Мелочи, дающие заметный эффект

- **Логотип из `index.html` в отдельный файл.** Сейчас `LOGO_DATA_URI` — одна строка на 157 КБ из 296 КБ файла, грузится при каждом заходе. Вынести в `logo.png`, подгружать лениво перед первым рендером КП.
- **Цвет шапки Telegram.** В `index.html` стоит `setHeaderColor('#121a1b')` при фоне `#080d12` — видна полоса другого цвета. В `deals.html` уже `#080d12`. Свести к одному значению.
- **Экранирование.** Значения полей подставляются в разметку как `value="${f.model}"` без `escapeHtml`. Кавычка в распознанном тексте обрезает поле, и причину не понять. Обернуть `f.model`, `f.carTrim`, `f.condition`, `f.notes` и строки `carLines`.
- **Нативные элементы Telegram:** `MainButton` вместо кнопки «Рассчитать» (с `showProgress()` во время запроса), `BackButton` для шитов и подразделов настроек, `HapticFeedback` на тумблерах и результате, `disableVerticalSwipes()` чтобы свайп по форме не закрывал мини-апп.
- **Распознавание цены.** В схему `api/parse-listing.js` добавить `price` и `priceCurrency` (enum `CNY/JPY/KRW/USD/RUB`). Подставлять в форму, только если валюта совпадает с валютой маршрута.
- **Возраст из даты выпуска.** Считать по `prodYear`/`prodMonth`: меньше 36 месяцев — `lt3`, меньше 60 — `t3to5`, иначе `gt5`. Показывать как «3–5 лет (из даты 07.2022)» с возможностью поправить вручную.
- **Таймауты.** У запроса к alta.ru в `api/customs.js` таймаута нет вовсе (у TKS есть, 8 с). У клиентских `fetch` в `fetchCustomsQuote`, `runListingParse`, `fetchAutoRates`, `bootGate` — тоже нет. Добавить `AbortSignal.timeout()`.
- **Уведомления владельцу в Telegram:** новая заявка на доступ (`api/_lib/access.js`, при создании записи `pending`) и одобрение доступа (`api/admin.js`). Сейчас владелец узнаёт о заявке, только если сам зайдёт в настройки.

## Что трогать НЕ надо

Это сделано правильно, «улучшение» будет откатом назад:

- **Проверка подписи `initData`** в `api/_lib/telegram.js` — канонический алгоритм, `timingSafeEqual`, срок годности. Не менять.
- **`mergeRatesState` / `mergeRoutesState`** в `index.html` — белый список полей, переживающих синхронизацию. Лечат реальный класс ошибок. Новое поле в `DEFAULT_CONFIG` по умолчанию берётся **из кода**, а не из сохранённого состояния.
- **Пиннинг российского корневого УЦ** в `api/rates.js` и `api/parse-listing.js`. Никогда не заменять на `rejectUnauthorized: false`.
- **Передача стоимости в TKS в исходной валюте** — таможенная стоимость считается по курсу ЦБ, а не по коммерческим курсам с наценкой. Юридически верно, выстрадано через реальное расхождение.
- **Раздельное хранение сделок** `deal:<id>` + индекс — не собирать в общий блоб.
- **Перечень этапов сделки в коде** `deals.html`, а не в редактируемых настройках.
- **Отсутствие сборщика и фреймворка.** Не вводить React/Vue/Vite. Разделить на несколько файлов можно, заводить сборку — нет.
- **Логику отправки из Блока 0.** Никаких веток под отдельные мессенджеры или платформы — это осознанное решение владельца.

Это не входит в задание, но нужно до начала работы над нативными приложениями iOS и Android. Сейчас вся предметная логика живёт в браузере, и для трёх клиентов её придётся писать трижды.

1. Расчёт на сервер: `POST /v1/quotes/calculate` с полной разбивкой, использованными курсами и статусом таможни.
2. Справочники через API: маршруты, комиссии, таблица доставки, города.
3. Сессии и токены вместо `initData` в каждом запросе. Заодно позволит работать на Android как обычное приложение с рабочего стола, где системное «Поделиться» работает полноценно.
4. Генерация КП на сервере — иначе 200 строк вёрстки придётся рисовать заново в Swift и Kotlin.
5. Расчёт как сущность со снимком результата и курсов, а не строка истории.
6. Этапы сделки на сервер.
7. PostgreSQL вместо блобов в KV, плюс объектное хранилище для фото и документов.
