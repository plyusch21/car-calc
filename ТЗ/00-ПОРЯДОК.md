# Порядок запуска ТЗ в Claude Code

Шестнадцать файлов. 01–14 выполнены; 11-б на паузе до прохождения KYC у посредника (зона Bright Data называется `che168u`, ТЗ будет обновлено перед запуском); 11 закрыто без результата (che168 закрыт проверкой на бота — см. РЕШЕНИЯ.md). Node.js на Mac установлен 17.09 — `node tools/calc-check.js` теперь основной способ проверки расчётов.

**Правило: одна сессия Claude Code за раз.** Две сессии в одной папке одновременно подхватывают правки друг друга в свои коммиты (так ТЗ 12 уехало в коммит ТЗ 11). Следующее ТЗ — только после того, как предыдущая сессия отчиталась о пуше. Каждый файл самодостаточен: в нём есть всё, что нужно исполнителю, ссылок на другие файлы и на переписку нет. Уже сделанное (деньги по сделке, «расчёт побеждает», шкала размеров, отступ от Telegram) в них не входит.

## Как запускать

Новая сессия Claude Code (приложение Claude на Mac → Code → New session, папка `car-calc`) на нужной модели. Файл перетащить из Finder в поле ввода как вложение и добавить одну строку:

> Выполни приложенное ТЗ целиком, без пропусков. После выполнения сам пройди раздел «Проверить» из этого ТЗ, напиши по каждому пункту — сошлось или нет, и только потом коммит и пуш в main по правилам CLAUDE.md.

Дальше — ждать. Когда исполнитель отчитается, что запушил, — написать в чат аналитику «NN готов»: сверка кода с ТЗ делается там, владелец глазами проверяет только то, что ему назовут отдельно. Следующий файл — только после того, как предыдущий закоммичен и выкачен: номера строк в каждом следующем файле уже сдвинутся, исполнитель сверяет их через `grep -n`, это заложено.

## Почему такой порядок

- 1 и 2 — быстрые правки страницы сделок, их лучше закрыть до того, как 4 начнёт менять карточку «Расчёты» на той же странице.
- 3 идёт строго перед 4: без общего файла страница сделок считать не умеет. После 3 приложение должно работать ровно как раньше — если что-то отличается, дальше не идти.
- 11 после 10: 10 ставит подписи карточки автозаполнения, 11 меняет одну из них под ссылки. В 11 первый пункт — проверка, что che168 открывается с серверов Vercel; если нет, исполнитель останавливается и докладывает.
- 8 идёт после всех функциональных ТЗ, чтобы номера строк и разметка больше не менялись; 9 — только после 08: светлая тема задаёт значения тем переменным, которые вводит 08. `08-макет-кобальт.html` — не ТЗ, а макет для исполнителя, его не запускать.
- 5 и 6 не зависят ни от чего, их можно сделать в любой момент, но после 4 спокойнее: `deals.html` к тому времени перестанет меняться крупно.

## Что делать, если исполнитель отступает от ТЗ

Согласованное отступление он обязан записать в `РЕШЕНИЯ.md` (правило из `CLAUDE.md`). Если он предлагает отступить, а причина непонятна — не соглашаться, а принести вопрос сюда: возможно, ТЗ неточное, и лучше поправить его, чем код.
