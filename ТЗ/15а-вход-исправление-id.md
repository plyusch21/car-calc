# ТЗ 15-а — Вход через сайт: брать Telegram id из claim `id`, а не `sub`

Что случилось: после ТЗ 15 владелец вошёл через Safari и попал в приложение **новым пользователем** «Дмитрий Плющай» со статусом pending, а не владельцем. Отладочная строка в логе Vercel показала причину:

```
api/login: вход через сайт, sub=3738326763498222169 id=393550074
```

`sub` в id_token Telegram — служебный идентификатор для входа на сайты, **не** Telegram user id. Настоящий user id (тот же, что `user.id` в `initData` мини-приложения) приходит в claim `id`. ТЗ 15 ошибочно предписывало `uid = sub`. Локальная проверка п. 2 из ТЗ 15 прошла на подделанном токене и ничего не показала — на будущее такие вещи проверяются только на боевом.

Модель: Sonnet. Пять минут.

## Где в коде (коммит `c1077e5`)

- `api/login.js`, `callback()`: строка ~196 `const uid = String(claims.sub);`; отладочная `console.log` ~202 с комментарием над ней ~200–201.
- `api/login.js`, `verifyIdToken()`: строка ~178 проверка `if (!claims.sub) …`.
- `api/_lib/access.js` — не трогать.
- Комментарии про `sub` в шапке `api/login.js` и в `CLAUDE.md` (grep `sub`).

## Что сделать

1. В `callback()`: `const uid = String(claims.id);` — только `id`. Если `claims.id` отсутствует или не число (`!/^\d+$/.test(String(claims.id ?? ''))`) — **ошибка**, а не откат на `sub`: `throw new LoginError('Telegram не передал идентификатор пользователя (id) — сообщите владельцу')`. Откат на `sub` запрещён: он молча создаёт фантомного пользователя, как и произошло.
2. Проверку `!claims.sub` в `verifyIdToken()` оставить (он есть всегда и нужен для целостности токена), проверку `id` добавить в `callback()` как в п. 1.
3. Отладочную строку `console.log(...)` и комментарий над ней убрать.
4. Убрать фантомную запись из доступов (ключ `3738326763498222169` в HASH `access`). В `api/admin.js` сейчас только `list`, `approve`/`revoke` (строка 45), `setDealsLevel` (68) — удаления нет. Добавить действие `remove` `{targetId}`: только для владельца (как остальные), `HDEL access <targetId>`, нельзя удалить самого себя и запись с `isOwner`. Клиент, карточка «Доступ к приложению» (`index.html` ~2572–2603): у записей со статусом `revoked` или `pending` рядом с «Разрешить» кнопка `btn secondary small` «Удалить» с `data-remove`; обработчик — `adminAction('remove', id)`, `toast('Запись удалена')`, `loadAdminCard()`. У `approved` кнопки «Удалить» нет — сначала «Закрыть». Подтверждение не нужно: запись при следующем входе человека создастся заново как pending.
5. Комментарии: в шапке `api/login.js` и в `CLAUDE.md` там, где написано про `sub` как id пользователя, — исправить на «`id` — Telegram user id; `sub` — служебный идентификатор OIDC, не использовать».

## Не трогать

Всё остальное из ТЗ 15: сессии, `authenticate`, клиент, гейт, `vercel.json`.
