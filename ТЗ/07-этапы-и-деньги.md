## 4. Деньги по новым этапам: взнос поступает на «Договор / Предоплата», удерживается на «Бронь»

**Решение владельца:** предоплата **поступает** при отметке «Договор / Предоплата — пройден». При «Бронь — пройден» она **удерживается** (закрепляется за машиной, больше не возвращается) — писать «предоплата удержана» и дату. «Без предоплаты» — состояние этапа «Договор / Предоплата».

**Сейчас:** всё завязано на `booking`: `moneyDue` (`:326`), `fixMoneyAmounts` (`:338`, `:347`), карточка «Деньги» (`:956-977`), подпись в строке этапа (`:1026`).

**Сделать:**
- `moneyDue`: `noDeposit = stageState(deal,'contract') === 'skip'`.
- `fixMoneyAmounts`: ключи `['contract','settle']`; сумма взноса фиксируется на `contract`. Совместимость: если у старой сделки `stages.booking.amount` есть, а у `contract` нет — в `migrateStages` перенести `amount` на `contract` (и `contract` в `done`, если он не `done`), у `booking` удалить `amount`.
- Карточка «Деньги», строка «Первоначальный взнос»: источник отметки — `stages.contract`. Подпись: `done` → `поступил DD.MM.YYYY` (или `поступил` без даты при `at===0`); `skip` → `без предоплаты`; иначе → `ожидается · при отметке «Договор / Предоплата»`. **Вторая подпись** — про удержание, только если `contract` не `skip`: `booking.state==='done'` → `удержана DD.MM.YYYY` (или `удержана` без даты); иначе → `будет удержана при отметке «Бронь»`. Рендерить второй строкой того же размера под первой (в `row(...)` добавить необязательный четвёртый аргумент `meta2`).
- Строка этапа в списке (`:1026`): `contract` в `done` с `amount` → `· N ₽ поступило` (как сейчас для `booking`); `booking` в `done`, когда `contract` не `skip` → `· предоплата удержана`.
- Лог (`api/deals.js`, блок `money` `:177-178`): для `booking → done` при `sAfter.contract && sAfter.contract.state !== 'skip'` дописывать ` — предоплата удержана`; сумма «поступило» — теперь у `contract`, логика та же.
- Тексты, где упоминается «при отметке «Бронь»» (`:977` и подсказка в блоке «Деньги»), — заменить по смыслу выше.

## 5. Каскад: отметка этапа закрывает всё до него, в любом состоянии

**Замечание владельца:** отметил «Расчёт — пройден», а «Таможня / Лаборатория» осталась «в процессе». Предыдущие этапы должны становиться «пройден», в каком бы состоянии они ни были.

**Сейчас:** `:1219-1223` — автозакрытие только для этапов **без** состояния (`!stages[prev.key] || !stages[prev.key].state`); «в процессе» пропускается.

**Сделать:** закрывать и `wip`: если `prev` в состоянии `''` или `wip` → `state:'done'`; для бывшего `wip` дату **сохранить** (`at` как была), заметку сохранить; для пустого — `at:0`, как сейчас. `skip` и `done` не трогать. Работает и при `val==='wip'`, и при `val==='done'` (как сейчас — блок выполняется для любого непустого `val`).

**Следствие для заморозки:** блок `:1244-1252` ставит `frozenAt` только когда отметили именно `customs`. Теперь `customs` может стать `done` каскадом (отметили «Стоянку» или «Расчёт»). Переписать блок на состояние, а не на ключ: после каскада `customsDone = stages.customs && stages.customs.state==='done'`; у источника `frozenAt = customsDone ? (src.frozenAt || Date.now()) : 0`; в `patch.calcs` — только если значение изменилось. Автопересчёт по `invoice`, закрытому каскадом, по-прежнему **не** запускается (курс на «никогда» не найти) — этот комментарий (`:1255-1259`) остаётся верным.

## 6. Откат: понижение этапа сбрасывает всё после него

**Замечание владельца:** вернул ранний этап в «в процессе» или «не пройден» — этапы после него остались пройденными, хотя по логике должны обнулиться.

**Сделать** в обработчике «Сохранить» (`:1203-1224`), там, где уже есть `prev` (прежняя отметка этого этапа):
- Ранг состояния: `''`→0, `wip`→1, `done`→2, `skip`→2. Если ранг нового `val` **меньше** ранга `prev.state` — это откат.
- При откате: у всех этапов **после** текущего (`list.slice(idx+1)`) отметки удалить (`delete stages[k]`), включая `skip` у «Отправки». Суммы денег на них пропадают вместе с отметками (`fixMoneyAmounts` для несуществующих отметок ничего не делает — проверить, что не падает).
- Заморозка: снимается правилом из части 5 (`customs` больше не `done` → `frozenAt = 0`).
- Курс инвойса: если после отката `stages.invoice` больше не `done` — у источника `ratesLock = null` (в том же `patch.calcs`), чтобы следующая отметка «Оплата инвойса — пройден» зафиксировала курс заново. Сейчас `ratesLock` нигде не снимается — это добавить.
- В шите этапа (`openStageSheet`, `:1178-1200`): если у этапа сейчас `done`/`wip`, а после него есть отметки — под селектом состояния уведомление `notice warn`: `Если вернуть этап в «не пройден» или «в процессе», все этапы после него сбросятся (N шт.)`. Показывать всегда при наличии отметок после — селект ещё не менялся, реагировать на его `onchange` не надо.
- В лог сервер и так пишет «снял отметку этапа «…»» по каждому удалённому (`describeChanges`, `sBefore` без `sAfter`) — проверить, что строк ровно столько, сколько сброшено.
