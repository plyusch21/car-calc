# ТЗ 11-б — Китай: автозаполнение по ссылке che168.com через посредника Bright Data

Задача: ссылка на объявление che168.com в «Автозаполнении» на маршруте «Китай» заполняет поля формы. Страницу объявления наш сервер получает **не с che168 напрямую** (сайт отдаёт программам только проверку на бота — см. ТЗ 11 п. 0 и `РЕШЕНИЯ.md`), а через сервис Bright Data Web Unlocker: наш сервер → API Bright Data → они открывают страницу своим браузером → нам приходит готовый HTML. Дальше разбор ровно по ТЗ 11 (`ТЗ/11-китай-che168.md`, разделы 1–8): скрытые поля страницы, справочник параметров по `specid`, ИИ только для перевода названия и описания.

Зачем: 90 % китайских объявлений менеджеры получают ссылками с che168; вставлять текст руками — медленно и с ошибками. Владелец решил 17.09: делать через посредника.

Почему посредник, а не свой обход проверки: обход ломается при каждом обновлении защиты, а при блокировке IP Vercel пострадал бы не только Китай. С посредником сервер Vercel к che168 вообще не обращается — блокировать нечего; сломается посредник — сломается только автозаполнение по ссылке, и приложение скажет «скопируйте текст».

Модель: Opus. Одна сессия, после пункта 0.

---

## 0. Подготовка — делает владелец (до запуска исполнителя)

1. Зарегистрироваться на brightdata.com (рабочая почта; карта на этапе пробы не нужна — у новых аккаунтов есть пробные средства; дальше Web Unlocker оплачивается по факту, около 1,5 $ за 1 000 запросов — при 200–300 ссылках в месяц это меньше 0,5 $).
2. В панели: **Proxies & Scraping → Web Unlocker API → Add zone**. Имя зоны — `che168` (латиницей). Остальное по умолчанию.
3. Там же взять **API key** (Account settings → API keys → создать; права по умолчанию).
4. Проверить, что посредник действительно отдаёт страницу: в панели зоны есть «Playground» / «Send your first request» — вставить ссылку `https://www.che168.com/dealer/449187/59075285.html` (или любую живую), формат `raw`, нажать. В ответе должен быть большой HTML, внутри — строка `car_infoid`. Если вместо этого короткий скрипт или ошибка — остановиться и написать аналитику; ТЗ дальше не запускать.
5. В Vercel: Project → Settings → Environment Variables → добавить `BRIGHTDATA_API_KEY` (ключ) и `BRIGHTDATA_ZONE` = `che168`, для Production и Preview. Ключ никуда, кроме Vercel, не вставлять (в чат Claude Code — тоже нет).
6. Написать исполнителю при запуске ТЗ: «ключи в Vercel добавлены, зона che168, playground страницу отдал».

## Что сделать

### 1. Запрос страницы через Bright Data

Новая функция `fetchViaUnlocker(url, {accept})`: `POST https://api.brightdata.com/request`, заголовки `Content-Type: application/json`, `Authorization: Bearer <BRIGHTDATA_API_KEY>`, тело `{ "zone": <BRIGHTDATA_ZONE>, "url": <url>, "format": "raw" }`. Таймаут 25 с (`AbortSignal.timeout`), один повтор при сетевом обрыве. Ответ — тело страницы как есть. Проверить кодировку: если Bright Data отдаёт байты страницы без перекодировки — декодировать GBK как в `decodeGbk()`; если уже UTF-8 (в ответе видна кириллица/иероглифы без «кракозябр» и `<meta charset=gb2312>` не соответствует) — не декодировать. Определять по факту: пробовать GBK и UTF-8, брать тот вариант, где в `car_carname` нет символа замены `�`.

Ключей нет в окружении → ошибка `che168: посредник не настроен (BRIGHTDATA_API_KEY)`. Ответ Bright Data не 200 → ошибка `che168: посредник вернул <статус>` с первыми 200 символами тела (без ключа).

`fetchChe168()` переписать так, чтобы страница объявления шла **только через посредника**; прямой запрос к `www.che168.com` из кода убрать совсем (не оставлять «сначала напрямую, потом через посредника» — прямой запрос и есть то, чего мы избегаем). Справочник `cacheapigo.che168.com/CarProduct/GetParam.ashx` — по ТЗ 11 п. 0 он проверкой не закрыт; запрашивать его напрямую с таймаутом 8 с, а при ошибке/неJSON — повторить через посредника; если и это не вышло — продолжать без справочника (ТЗ 11, раздел 3).

### 2. Разбор — по ТЗ 11

Реализовать разделы 1–6 ТЗ 11 (`ТЗ/11-китай-che168.md`) без изменений: скрытые поля (`car_carname`, `car_price` × 10 000, `car_mileage` × 10 000, `car_firstregtime`, `car_specid`, `car_isselled`), блок `ul.basic-item-ul`, описание `#messageBox`, справочник по `specid` (см³, л.с./кВт, КПП, привод, топливо), правила маппинга, дата выпуска из описания `出厂` с приоритетом над датой учёта, ИИ только для `model/carTrim/condition/notes` с резервом GigaChat, структурные значения перекрывают ИИ, ответ в формате Encar (`source:'che168'`). Ветка в обработчике — на месте нынешней заглушки 1444–1447.

### 3. Время

Цепочка: Bright Data (обычно 3–15 с) → справочник (1–2 с) → ИИ (3–8 с, параллельно со справочником). Итого до 25 с в плохом случае.
- Клиент: для ссылок che168 таймаут `runListingParse` поднять до 45 с (только когда `payload.text` — ссылка che168; остальные пути — 30 с как сейчас). Пока ждём — текст кнопки «Распознаю… (через посредника, до 30 с)».
- Сервер: проверить лимит времени функции. В Vercel → Project → Settings → Functions посмотреть «Max Duration» по умолчанию для проекта; если меньше 60 с — задать в `vercel.json` для `api/parse-listing.js`: `{ "src": "api/parse-listing.js", "use": "@vercel/node", "config": { "maxDuration": 60 } }` (формат `builds` в проекте уже используется). Задеплоить и убедиться, что запрос на 20+ с не обрывается с 504.

### 4. Диагностика

`debugChe168()` и кнопка «7. Проверить che168» на `/diag`: тот же путь через посредника; в ответ добавить `via:'brightdata'`, `unlockerStatus`, `unlockerMs` (сколько ждали посредника), `charset` (что выбрали). Рядом кнопка «8. Разобрать che168» — полный разбор, вывод JSON полей, чтобы владелец сверял без калькулятора.

### 5. Клиент

Карточка «Автозаполнение», маршрут `china`: placeholder `Введите текст или ссылку`, подсказка одной строкой `Можно вставить ссылку на объявление che168.com`. При ошибке посредника менеджер видит текст ошибки под кнопкой, как сейчас с Encar; форма не меняется.

### 6. Учёт и предохранители

- Каждый вызов посредника писать в KV счётчик `stats:brightdata:<YYYY-MM>` (`INCR`) — чтобы владелец видел расход; показать число на `/diag` в блоке che168 («запросов к посреднику в этом месяце: N»).
- Кэш: результат разбора по `infoid` хранить в KV 24 часа (`cache:che168:<infoid>`, `SET … EX 86400`) — повторная вставка той же ссылки (пересчёт, второй менеджер) не тратит запрос посредника.
- Ссылка на che168 на **любом** маршруте обрабатывается одинаково (маршрут на сервер не приходит).

## Допущения (владелец может возразить)

- Посредник — Bright Data Web Unlocker (отдаёт сырой HTML, наш разбор из ТЗ 11 работает без изменений). Их готовый «che168 scraper» с бесплатными 5 000 страниц в месяц не взят: он отдаёт свой набор полей неизвестного состава и работает до минуты — под наш разбор пришлось бы подстраиваться вслепую. Если после регистрации выяснится, что у Web Unlocker нет пробных средств, а платить не хочется — скажи, переделаем ТЗ под их che168 scraper.
- Кэш на 24 часа: цена на объявлении за сутки меняется редко; повтор через сутки — новый запрос.
- Правила che168 запрещают автоматический сбор; сбор делает посредник по своим условиям, у нас — единичные запросы по ссылкам, которые менеджер и так открывает руками. Риск принят владельцем 17.09.
