# ТЗ 03. Вынос формулы в общий файл `lib/calc.js`

Модель: **Fable**. Одна сессия, один коммит с пушем. Это первая половина большой задачи «автоматический пересчёт расчёта по этапам сделки» (вторая — ТЗ 04). Поведение приложения после этого ТЗ **не меняется ни в чём** — только код формулы переезжает в общий файл, чтобы страница сделок могла считать сама.

Перед началом прочитать `.claude/map.md`. `index.html` и `deals.html` целиком не читать — только нужные диапазоны через `sed -n`, искать через `grep -n`. Номера строк в этом файле — по коду на коммите `360be86`; перед каждой правкой сверять `grep -n`. После правок, сдвигающих строки, — `bash tools/mapgen.sh`. Коммит и пуш в `main` — по правилам `CLAUDE.md`. Отступления от этого файла, согласованные по ходу, — записью в `РЕШЕНИЯ.md`.

## Зачем

Владелец хочет, чтобы при отметке этапов сделки («Оплата инвойса — пройден», «Таможня / Лаборатория — в процессе») привязанный расчёт пересчитывался сам, без перехода в калькулятор. Страница сделок сейчас не умеет считать: формула, таблица доставки и сборка запроса к ТКС живут только в `index.html`. Дублировать их нельзя (формула должна быть в одном месте — принятое решение), значит — общий файл, который подключают обе страницы.

## Что есть сейчас (проверено)

- Формула и всё, что ей нужно, живут только в `index.html`: `DEFAULT_CONFIG` (`:423-528`, маршруты, доставка по городам, описания курсов), слияние с сохранёнными настройками `mergeRatesState` / `mergeRoutesState` / `applyStoredConfig` / `deepMerge` (`:529-574`, `:652`), `ENGINE_TYPES` (`:688`), `num` (`:709`), `CUSTOMS_AGE_CODE` (`:852`), сборка запроса к ТКС `fetchCustomsQuote` (`:854-903`), `deliveryPrice` (`:926`), `convertToRub` (`:935-943`), `calcDeal` (`:948-973`), правило «что из ответа ТКС идёт в `customsAuto`» (`:1600-1601`: для ЕАЭС без полной пошлины — только утильсбор). Все они читают глобальный `CONFIG`.
- Настройки (`state:config`) страница сделок уже умеет получать — `loadCalcHistory` (`deals.html:1283-1295`) делает `action:'get'` к `/api/state` и берёт оттуда только `history`; в том же ответе есть `config`.
- История курсов: `rates:hist:<ID>` — sorted set, запись на каждое успешное обновление, три месяца (`api/_lib/rateHistory.js`); отдаётся через `action:'getRateHistory'` (`api/state.js:126-133`).
- Пересчёт из сделки сейчас — переход в калькулятор через `localStorage['bk_recalc_v1']` (`deals.html:1087-1096` → `index.html:2956-2968`), там кнопка «Сохранить в сделку … и отправить» (`:1686-1690`, `:1761-1779`) → `action:'recalcDealCalc'` (`api/deals.js:438-467`).
- Автоматического пересчёта при отметке этапа **нет**.
- `vercel.json`: всё, что не описано в `routes`, уходит на `index.html` (`:35`); статика перечисляется в `builds` поимённо.

## Что нужно получить

Формула и её окружение выносятся из `index.html` в `lib/calc.js`, который подключают обе страницы обычным `<script src="/lib/calc.js?v=1">` (без модулей и сборщиков — принятое решение остаётся в силе; это один статический файл). Файл объявляет один глобальный объект `BkCalc` и ничего больше в глобальную область не пишет; в конце — `if (typeof module !== 'undefined') module.exports = BkCalc;`, чтобы его можно было прогнать в Node для проверки.

Что переезжает (и в `index.html` удаляется): `DEFAULT_CONFIG`, `deepMerge`, `mergeRatesState`, `mergeRoutesState`, `applyStoredConfig`, `ENGINE_TYPES`, `num`, `CUSTOMS_AGE_CODE`, `deliveryPrice`, `convertToRub`, `calcDeal`, сборка тела запроса к ТКС (из `fetchCustomsQuote` — только формирование `payload`, без `fetch` и без `initData`), правило `customsAutoTotal`.

Функции в библиотеке **не читают глобальный `CONFIG`** — конфиг передаётся аргументом: `BkCalc.calcDeal(route, f, cfg, ratesValues)`, `BkCalc.deliveryPrice(cfg, city, bodyIdx)`, `BkCalc.customsPayload(cfg, route, f)`, `BkCalc.customsAutoTotal(cfg, route, res)`. Последний аргумент `calcDeal` — необязательная подмена курсов `{JPY: 0.57, KRW_USDT: …, USDT_RUB: …, CNY: …}`; если передан, `convertToRub` берёт значения оттуда, иначе `cfg.rates[id].value`. Это заменяет любую идею временно подменять `CONFIG.rates` — подмены нет, есть аргумент.

Чтобы не трогать сотню мест в `index.html`, там остаются **тонкие обёртки с прежними именами**: `function calcDeal(route,f){ return BkCalc.calcDeal(route,f,CONFIG); }`, то же для `deliveryPrice`, `convertToRub`, `num`, `applyStoredConfig`; `const ENGINE_TYPES = BkCalc.ENGINE_TYPES;`, `const DEFAULT_CONFIG = BkCalc.DEFAULT_CONFIG;`, `const CUSTOMS_AGE_CODE = BkCalc.CUSTOMS_AGE_CODE;`. `fetchCustomsQuote` остаётся в `index.html`, но тело запроса берёт из `BkCalc.customsPayload(CONFIG, route, f)` и добавляет `initData`. `doCalc` (`:1600-1601`) берёт сумму из `BkCalc.customsAutoTotal(CONFIG, route, res)`.

Порядок в `index.html`: `<script src="/lib/calc.js?v=1">` стоит **перед** основным `<script>`, потому что `let CONFIG = applyStoredConfig(...)` (`:574`) выполняется при загрузке. В `deals.html` — так же, перед основным скриптом.

`vercel.json`: в `builds` добавить `{ "src": "lib/calc.js", "use": "@vercel/static" }`, в `routes` **выше** строки-ловушки `/(.*)` добавить `{ "src": "/lib/(.*)", "dest": "/lib/$1" }`. Без этого файл отдастся как `index.html` и обе страницы упадут. `?v=1` в подключении — ручная защита от кэша: при каждом изменении `lib/calc.js` номер поднимать в обоих html.

## Проверка — обязательная, коммит без неё не делать

После переезда всё должно давать ровно те же числа. Переезжают три разные вещи, и проверять надо все три: сама формула (`calcDeal`), сборка запроса к ТКС (`customsPayload` — для электро объём 0 и мощность в отдельном поле, каталожная стоимость вместо цены) и правило, что из ответа ТКС идёт в сумму (`customsAutoTotal` — для ЕАЭС без полной пошлины только утильсбор). Поэтому набор — восемь расчётов разных категорий, таможня в них **автоматическая** (через ТКС), не ручная:

| № | Маршрут | Двигатель | Возраст | Особенность |
|---|---|---|---|---|
| 1 | Япония | бензин 1 500 см³, 100 л.с. | 3–5 лет | базовый |
| 2 | Япония | **электро**, 150 кВт | до 3 лет | мощность в кВт, объём не передаётся |
| 3 | Япония | дизель 3 000 см³, 200 л.с. | старше 5 лет | крупный объём, старый |
| 4 | Корея | бензин 2 000 см³, 150 л.с. | до 3 лет | **каталожная стоимость** включена и выше цены |
| 5 | Корея | **электро**, 100 кВт | 3–5 лет | |
| 6 | Китай | бензин 1 500 см³, 110 л.с. | 3–5 лет | |
| 7 | Китай | **электро**, 200 л.с. | до 3 лет | мощность в л.с. у электро |
| 8 | ЕАЭС | бензин 1 600 см³, 120 л.с. | 3–5 лет | тумблер полной пошлины **выключен** — только утильсбор |

Цена — 1 000 000 в валюте маршрута, доп. расходы 50 000, доставка в Москву по таблице, тип кузова один и тот же.

1. До правок: в Browser pane посчитать все восемь, для каждого записать три числа: таможня (строка «Расчёт TKS»), инвойс в рублях и «Итого», плюс четыре курса из виджета. Записать в `tools/calc-fixture.md` — он остаётся в репозитории.
2. После правок, в тот же день, курсы не трогая: те же восемь → все три числа в каждом совпадают копейка в копейку; чек и КП выглядят так же. Если в каком-то расчёте разошлась только таможня — сначала повторить его: ТКС при лимите подменяется резервом alta.ru, и это может дать другое число без вины кода; расхождение считается ошибкой, только если повторяется.
3. `tools/calc-check.js`: `require('../lib/calc.js')`, конфиг — `applyStoredConfig(null)` с подставленными вручную значениями курсов и таможней из `calc-fixture.md`, те же восемь форм → печатает восемь итогов **и** восемь тел запроса к ТКС (`customsPayload`). Первый прогон — эталон, записать его в тот же `calc-fixture.md`. Это регрессионный тест на будущее: `node tools/calc-check.js` должен печатать эталон.
4. `node --check` на извлечённом скрипте `index.html` и на `lib/calc.js`. Открыть `/` и `/deals` на деплое — консоль без ошибок.

Коммит «lib/calc.js: формула вынесена в общий файл, поведение не изменилось».

## ЧТО НЕ ТРОГАТЬ

- Сами вычисления в `calcDeal`/`convertToRub`/`deliveryPrice` — переезжают как есть, ни одна формула не меняется. Новый четвёртый аргумент `calcDeal` (подмена курсов) добавляется, но в этом ТЗ нигде не используется.
- `fetchCustomsQuote` — кроме замены тела запроса на `BkCalc.customsPayload`.
- КП (`.kp-*`, `buildKpHtml`), `shareResult`, историю расчётов, страницу сделок (`deals.html` только получает тег `<script src>` — больше ничего).
- `api/*` — сервер в этом ТЗ не меняется.
- `--radius`, шапки карточек, цвета — вёрстку не трогать вообще.
