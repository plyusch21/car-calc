Коммит и пуш в `main` — по правилам `CLAUDE.md`. Отступления от этого файла, согласованные по ходу, — записью в `РЕШЕНИЯ.md`.

## Как это должно работать — словами владельца

Расчёт, привязанный к сделке, проходит три состояния, привязанные к этапам, и **без отдельных нажатий** — отметил этап, расчёт обновился сам:

1. **«Оплата инвойса — пройден».** Деньги за машину ушли, курс на этот день — окончательный. Забронированный расчёт пересчитывается целиком (инвойс, таможня, всё) по курсам **на дату, вписанную в этап** (если она сегодняшняя — по текущим). Курс инвойса с этого момента зафиксирован. Остальные расчёты из сделки удаляются (уже сделано). Кнопка «пересчитать» остаётся.
2. **«Таможня / Лаборатория — в процессе».** Машина пришла, начинается оформление. Пересчитываются **только таможенные платежи** на сегодня. Инвойс остаётся по зафиксированному курсу.
3. **«Таможня / Лаборатория — пройден».** Всё оплачено. Расчёт замораживается: никаких пересчётов, кнопка исчезает. Снял отметку — заморозка снимается.

До первого из этих этапов расчёт живёт как сейчас: кнопкой пересчитывается целиком по свежим курсам сколько угодно раз.

- В `index.html` обёртки с прежними именами (`calcDeal(route,f)` → `BkCalc.calcDeal(route,f,CONFIG)` и т.д.), `RECALC_CTX` и переход из сделки через `localStorage['bk_recalc_v1']` (`deals.html:1087-1096` → `index.html:2956-2968`), кнопка «Сохранить в сделку … и отправить» (`index.html:1686-1690`, обработчик `:1761-1779`) → `action:'recalcDealCalc'` (`api/deals.js:438-467`).

## Что нужно получить

### Шаг 1 — снимок расчёта получает два новых поля

- `ratesLock` — курсы, по которым посчитан инвойс, зафиксированные при оплате инвойса: `{ at: <ts отметки>, values: { JPY, KRW_USDT, USDT_RUB, CNY }, source: 'current' | 'history', missing: ['CNY'] }`. `source` — откуда взяты, `missing` — для каких валют истории на ту дату не нашлось и взят текущий курс (обычно пусто). Пусто, пока инвойс не оплачен.
- `frozenAt` — метка времени, после которой расчёт не меняется. Ставится при «Таможня / Лаборатория — пройден», снимается, если эту отметку убрали.

`api/deals.js`: `saveDeal` (белый список снимка, `:330-357`) хранит оба поля как есть (`ratesLock` — объект или `null`, `frozenAt` — число или `0`); `recalcDealCalc` принимает `parts` и, если пришёл, `ratesLock`; при `frozenAt` на снимке отвечает `409` «расчёт зафиксирован после оплаты таможни» и ничего не меняет. В лог (`:465`) писать: `пересчитал расчёт «…»: N ₽ (курсы на DD.MM.YYYY)` для полного пересчёта и `пересчитал таможню в расчёте «…»: N ₽` для таможенного.

### Шаг 2 — курсы на дату: серверное действие

`api/state.js`, рядом с `getRateHistory` (`:126`): `action:'getRatesAt'`, вход `{ at: <ts> }`, выход `{ values: {JPY, KRW_USDT, USDT_RUB, CNY}, missing: [...] }`. Для каждой из четырёх валют — последняя запись истории с `entry.at <= at`; если такой нет — валюта попадает в `missing`, значение не отдаётся (клиент подставит текущее). Момент `at` считает клиент: конец дня, вписанного в этап, по его локальному времени (`parseDdMmYyyy` + 24 ч − 1 мс), чтобы сервер не гадал про часовые пояса.

### Шаг 3 — пересчёт внутри `deals.html`

Одна функция `recalcBookedCalc(deal, mode, atTs)`, `mode` ∈ `'full' | 'customs'`:

1. Источник — забронированный расчёт, а если он один — он. Нет источника (несколько без брони или ни одного) — вернуть «нечего пересчитывать», без ошибок.
2. Конфиг: `loadCalcHistory` расширить до `loadCalcState`, который кладёт в `state.calcConfig = BkCalc.applyStoredConfig(data.config)` и в `state.calcHistory` — один запрос, один раз за загрузку страницы.
3. Курсы:
   - `full`, дата этапа — сегодня → `values` из `state.calcConfig.rates[id].value` (это те же курсы, что показывает калькулятор: их он обновляет при каждом своём открытии, отдельно ходить к источникам курсов страница сделок не будет), `source:'current'`;
   - `full`, дата раньше сегодняшней → `getRatesAt`, недостающие валюты — из конфига, `source:'history'`, `missing` — как вернул сервер;
   - `customs` → `ratesLock.values`; если `ratesLock` нет (инвойс отметили, а пересчёт тогда не прошёл) — работать как `full` на сегодня и зафиксировать.
4. Таможня: если `form.customsOverride` — не трогать (ручная таможня — это таможня). Иначе `POST /api/customs` с `BkCalc.customsPayload(cfg, route, form)` + `initData`, таймаут 25 с как в калькуляторе; `form.customsAuto = String(Math.round(BkCalc.customsAutoTotal(cfg, route, res)))`. **Ошибка ТКС — пересчёт прерывается целиком**, ничего не сохраняется, тост «Таможня не пересчиталась: <текст> — нажми «пересчитать» позже», в карточке расчёта строка `требуется пересчёт` до успешного прогона.
5. `r = BkCalc.calcDeal(route, form, cfg, values)`; `parts = {broker:r.broker, agent:r.agent, delivery:r.delivery}`.
6. `recalcDealCalc` с `{ total:r.total, form, parts, ratesLock }` — `ratesLock` только в режиме `full`.
7. Пока идёт — в карточке «Расчёты» у снимка строка `пересчитываю…`, кнопки заблокированы; по завершении — перечитать сделку (как после `saveDeal`).

**Когда вызывается** (обработчик «Сохранить» в шите этапа, после `saveDeal`, `deals.html:1129-1166`):
- `invoice` → `done`: `recalcBookedCalc(d, 'full', endOfDay(дата этапа))` — после существующего удаления лишних расчётов.
- `customs` → `wip`: `recalcBookedCalc(d, 'customs')`.
- `customs` → `done`: в тот же `saveDeal` — `frozenAt = Date.now()` у источника; пересчёта нет.
- `customs` из `done` в любое другое: `frozenAt` убрать.
- Автозакрытие предыдущих этапов (`:1144-1148`) пересчёт **не** запускает: отметил «Выдан авто» — «Оплата инвойса» закрылась задним числом без даты, курс на «никогда» не найти. Такой снимок просто остаётся как был.

**Кнопка «пересчитать по курсам»** в карточке (`:1034`, обработчик `:1087`): остаётся, режим — по состоянию снимка: `frozenAt` → кнопки нет; `ratesLock` есть → `'customs'`; иначе `'full'` на сегодня. Переход в калькулятор через `bk_recalc_v1` кнопка больше не делает.

**Отдельная ссылка «открыть в калькуляторе»** рядом — прежний переход через `bk_recalc_v1` (он нужен, чтобы отправить клиенту КП по актуальной сумме: там кнопка «Сохранить в сделку и отправить»). Калькулятор в этом режиме должен уважать зафиксированные курсы: в `payload` добавить `ratesLock`, `RECALC_CTX` его хранит, обёртка `calcDeal` в `index.html` передаёт `RECALC_CTX && RECALC_CTX.ratesLock ? RECALC_CTX.ratesLock.values : undefined` четвёртым аргументом, виджет курса показывает `курс зафиксирован DD.MM.YYYY по оплате инвойса` и не открывает редактор. При `frozenAt` ссылки нет. Сохранение из калькулятора при `frozenAt` получит `409` — показать текст ошибки, это правильно.

### Карточка «Расчёты» показывает состояние

Под суммой источника строка мелким (класс `u-hint` — шкала размеров из ТЗ-интерфейс уже применена, числа в px не писать):
- ни `ratesLock`, ни `frozenAt` → ничего;
- `ratesLock` → `курсы на DD.MM.YYYY (оплата инвойса)`; если `missing` не пусто — ` · для <валюты> истории нет, взят текущий`;
- `frozenAt` → `расчёт зафиксирован DD.MM.YYYY`, кнопки и ссылки нет;
- после неудачного пересчёта → `требуется пересчёт` красным (`var(--danger)`), пока не пройдёт удачный (хранить в `state`, не в записи сделки).

Подсказка `:1038` про удаление остальных расчётов остаётся.

### Связь с блоком «Деньги»

Брокер, агент и доставка — рублёвые, от курсов не зависят; блок «Деньги» на пересчёты не реагирует. `parts` обновляется при каждом сохранении.

## Проверка

1. `node tools/calc-check.js` печатает эталон из `tools/calc-fixture.md` — если нет, ТЗ 03 сломано, дальше не идти.
2. `node --check` `api/state.js`, `api/deals.js`; скрипты обоих html; `node tools/calc-check.js` печатает эталон.
3. Сделка с двумя расчётами, один забронирован. «Оплата инвойса — пройден» с сегодняшней датой → лишний удалился, «пересчитываю…», сумма обновилась, строка «курсы на сегодня (оплата инвойса)». В Upstash у снимка `ratesLock.source === 'current'`.
4. Другая сделка, «Оплата инвойса — пройден» с датой 10 дней назад → `ratesLock.source === 'history'`, значения совпадают с окном «История курса» в калькуляторе за тот день. Дата 4 месяца назад → `missing` со всеми четырьмя, текущие курсы, подпись про это.
5. Поменять курс йены в редакторе на заметно другой. «Таможня — в процессе» → инвойс в сумме **тот же**, что после п. 3 (проверить по чеку через «открыть в калькуляторе» — виджет показывает «зафиксирован», инвойс не сдвинулся), таможня пересчитана. Вернуть курс.
6. Отключить сеть до ТКС (например, временно неверный `customsProxyUrl` в конфиге или выключить Wi-Fi на момент запроса) → тост, сумма не изменилась, «требуется пересчёт»; включить, нажать «пересчитать» → прошло.
7. «Таможня — пройден» → кнопки нет, «расчёт зафиксирован»; `recalcDealCalc` руками → 409. Снять отметку → кнопка вернулась.
8. Расчёт с ручной таможней: «Таможня — в процессе» → ТКС не вызывается, сумма не меняется, лог пишет пересчёт таможни с той же суммой — допустимо, но лучше в этом случае пересчёт пропустить с тостом «таможня введена вручную — пересчитывать нечего».
9. Сделка без расчётов: отметки этапов ничего не запускают и ничего не пишут.
10. Отметить сразу «Выдан авто» на сделке с расчётом → расчёт не пересчитан, без ошибок.

- `lib/calc.js` — формулу не менять; подмена курсов только через четвёртый аргумент `calcDeal`. Если что-то в библиотеке всё же пришлось поправить — `node tools/calc-check.js` обязан печатать прежний эталон.

- Удаление лишних расчётов при оплате инвойса (`deals.html:1161-1164`).
- КП (`.kp-*`, `buildKpHtml`), `shareResult`, `fetchCustomsQuote`.
- Общую историю расчётов (`state.history`) — пересчёты в неё по-прежнему не попадают.
- `api/customs.js` — вызывается тем же запросом, что и из калькулятора; лимит ТКС (`tks:ratelimit`) и резерв alta.ru работают как есть.
