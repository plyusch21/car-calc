## 1. Шапки карточек в `deals.html` — как в калькуляторе

**Решение владельца:** страница сделок должна выглядеть так же, как калькулятор.

**Сейчас:** `deals.html:60`
```css
.card h2{ font-size:var(--fs-base); text-transform:uppercase; letter-spacing:.05em; color:var(--muted); margin:0 0 var(--sp-3); font-weight:600; }
```

**Заменить на** стиль из `index.html:98-103` — дословно, без поправок: после шкалы размеров у `.card` в обоих файлах один и тот же внутренний отступ `var(--sp-4)` (`deals.html:59`, `index.html:97`), поэтому отрицательные отступы совпадают:
```css
.card h2{
  background:#2f7dd122; color:#e6edf1; text-align:center; text-transform:uppercase;
  font-size:var(--fs-sm); font-weight:600; letter-spacing:0.08em; padding:var(--sp-3) var(--sp-4);
  margin:calc(var(--sp-4) * -1) calc(var(--sp-4) * -1) var(--sp-4); border-bottom:1px solid rgba(47,125,209,.45);
  border-radius:13px 13px 0 0;
}
```

Плотный вариант (`.receipt-title`, синий `#255aa1`) в `deals.html` не нужен — там нет карточки чека.

**Проверить:** открыть карточку сделки и профиль контрагента в Browser pane — все заголовки `<h2>` (включая новый блок «Деньги») получили подложку, ни один не вылез за скругление карточки.

## 2. Текст про обновление курсов — «раз в сутки»

**Решение владельца:** обновление по расписанию остаётся раз в сутки, на платный тариф не переходим. Текст в интерфейсе привести к реальности.

**Сейчас** три места говорят «дважды»:
- `index.html:1138` — `Обновляется дважды в сутки и при открытии приложения`
- `index.html:2761` — то же в редакторе курса
- `api/rates-refresh.js:4` — комментарий `0:00 и 12:00 МСК`

**Заменить:**
- в обоих местах `index.html` → `Обновляется раз в сутки и при открытии приложения`
- в `api/rates-refresh.js:4` → `(см. vercel.json — раз в сутки в 0:00 UTC; лимит тарифа Vercel Hobby, дважды в сутки крон не разрешён)`

`vercel.json` не трогать — там уже `0 0 * * *`.

## 3. Архив расчётов — по пользователям

**Решение владельца:** архив разделить по пользователям так же, как историю.

**Сейчас:** `api/state.js` — история уже разнесена (`historyKey = 'state:history:' + auth.uid`, строка 45), архив — один общий ключ:
- чтение: `:49` — `kv('GET', 'state:archive')`
- запись: `:109-111` — `action === 'saveArchive'` → `kv('SET', 'state:archive', ...)`

**Сделать** по образцу истории:
1. Рядом с `historyKey` завести `const archiveKey = 'state:archive:' + auth.uid;`
2. В `get` и в `saveArchive` заменить `'state:archive'` на `archiveKey`.
3. Разовую миграцию — как для истории в `:52-56`: если персонального ключа нет, а старый общий `state:archive` есть — прочитать общий, записать под персональный ключ, общий не удалять (он безвреден и пригодится, если второй пользователь появится до того, как старый архив станет неактуальным).
4. Обновить комментарий в шапке файла (`:13-15`): убрать «still shared».

Клиент (`index.html`, `saveArchive` `:646-650` и загрузка в `bootGate` `:2926-2927`) менять не нужно — он не знает имени ключа.

**Проверить:** после деплоя открыть приложение, архив на месте (миграция сработала). Записать новый расчёт — появился в архиве. В Upstash появился ключ `state:archive:<твой uid>`.

## 4. Тумблер «каталожная стоимость» сбрасывает таможню

**Решение владельца:** да, сбрасывать при переключении.

**Сейчас:** `index.html:1534`
```js
const customsValT = document.getElementById('customsValueOverrideToggle'); if(customsValT) customsValT.onclick = ()=>{ f.customsValueOverride=!f.customsValueOverride; renderCalc(c); };
```
Переключение тумблера меняет то, что уйдёт в TKS (каталожная стоимость вместо цены или наоборот), но посчитанная таможня остаётся от прежнего варианта.

**Заменить на:**
```js
const customsValT = document.getElementById('customsValueOverrideToggle'); if(customsValT) customsValT.onclick = ()=>{ f.customsValueOverride=!f.customsValueOverride; invalidateCustomsAuto(f); renderCalc(c); };
```

`invalidateCustomsAuto` (найти по `grep -n '^function invalidateCustomsAuto'`) уже сам не трогает ничего при включённом ручном вводе таможни — дополнительных проверок не нужно.

**Проверить:** ввести цену, включить каталожную, ввести её, «Рассчитать» → выключить тумблер → результат должен исчезнуть, пока не нажмёшь «Рассчитать» снова.

## 5. Коды ошибок: 403 на «нет прав», 422 на «не аукционный лист»

**Решение владельца:** исправить.

**Сейчас** в `api/deals.js` отказ в доступе к конкретной записи отдаётся кодом 400 («неправильный запрос»), хотя запрос правильный — просто нельзя:
- `:269` — `нет доступа к этой сделке`
- `:283` — `эту сделку вам править нельзя`
- `:401` — `эту сделку вам удалять нельзя`
- `:444` — `эту сделку вам править нельзя`
- `:481` — `нет доступа к этому контрагенту`
- `:505` — `редактировать существующих контрагентов может только владелец…`
- `:573` — `удалять контрагентов может только владелец`
- `:590` — `выгрузка доступна при полном уровне доступа`

**Заменить** в этих восьми местах `res.status(400)` → `res.status(403)`. Остальные `400` в файле (валидация — «не указан тип», «нет id» и т.п.) не трогать, там код верный.

В `api/parse-listing.js:1291` ответ «На фото не удалось распознать аукционный лист» отдаётся с `200`. Это не сбой, а осмысленный отказ, и `200` тут был осознанным — но клиент всё равно читает поле `error`, а в панели Vercel это выглядит как успех. **Заменить на `422`** (Unprocessable Content — «данные получены, обработать нельзя»). Клиент (`runListingParse` в `index.html`, найти по `grep -n`) проверяет `data.error`, а не `res.ok`, — поведение не изменится; убедиться в этом перед правкой.

**Проверить:** `node --check` на обоих файлах. Под пользователем с уровнем «только свои» открыть чужую сделку — тост с прежним текстом, в логах Vercel — 403.

## 6. Формат числа в виджете курса — запятая

**Мелочь, идёт паровозом.**

**Сейчас:** `index.html:1045` — `<div class="rw-value">${data.value.toFixed(4)}</div>` → юань показывается как `13.1900`, с точкой. Везде в приложении разделитель — запятая (`fmtRate`, найти по `grep -n '^function fmtRate'`).

**Заменить на:** `${data.value.toFixed(4).replace('.', ',')}`.
