## 4. Тема оформления — за аккаунтом, а не за устройством

Сейчас (ТЗ 09): выбор темы `bk_theme_v1 = {mode:'dark'|'light'|'auto'}` лежит только в `localStorage` устройства — на телефоне и на компьютере может быть выбрано разное. Владелец решил: тема должна ехать за пользователем Telegram.

Где в коде:
- `index.html` — `BkTheme` в `<head>` (строки ~13–55: `KEY`, `setMode()`, `apply()`, `mode()`, `effective()`), настройки темы `bindThemeSettings()` (`grep -n 'themeAutoToggle'`, вызовы `BkTheme.setMode` ~2421 и ~2426), загрузка после проверки доступа — `bootGate()`, ответ `/api/auth` в `authRes` (~2947–2952), затем запрос `/api/state` `action:'get'`.
- `deals.html` — копия `BkTheme` в `<head>`, `boot()` → `api('bootstrap')`.
- `api/auth.js` — ответ `{status, isOwner, name, …}` (строки 28–31); запись пользователя — `api/_lib/access.js`, `authenticate()`, хранится в KV `HSET access <uid>` (строки 13–41), в ней уже есть `status`, `isOwner`, `name`, `username`.
- `api/state.js` — действия по `body.action` (44–…), `auth.uid` доступен после `authenticate`.
- `api/deals.js` — `action === 'bootstrap'` (274), ответ уже содержит `me`.

Сделать:
- Хранить тему в записи пользователя в KV: поле `theme: 'dark'|'light'|'auto'` в объекте `access/<uid>` (там же, где `name`, `isOwner`). Это личная настройка — **не** в `state:config` (он общий на всех).
- `api/state.js`: новое действие `saveTheme` — `{theme}` → валидировать (`dark|light|auto`), записать в `access/<uid>` через `HSET`, ответить `{ok:true}`. Без версий и конфликтов: последняя запись побеждает.
- Отдавать тему при загрузке без лишнего запроса: `api/auth.js` добавляет в ответ `theme` из записи (нет поля → `null`); `api/deals.js` `bootstrap` — то же в `me.theme`.
- Клиент, обе страницы: при старте тема, как и сейчас, ставится из `localStorage` до первой отрисовки (без вспышки). Когда пришёл ответ `/api/auth` (index) или `bootstrap` (deals): если `theme` из ответа не `null` и отличается от локального `mode` — применить `BkTheme.setMode(theme)` и обновить `localStorage`. Если в ответе `null` (у пользователя ещё нет сохранённой темы), а локально выбрано не по умолчанию — один раз отправить локальный выбор на сервер (`saveTheme`), чтобы он стал аккаунтным.
- При смене темы в настройках (`BkTheme.setMode` из `bindThemeSettings`) — после локального применения отправить `saveTheme` (fire-and-forget, ошибку сети показать `toast`, локальный выбор остаётся). Автопереключение по `themeChanged` при режиме `auto` на сервер **не** шлёт — режим и так `auto`.
- `localStorage` остаётся кэшем последнего известного значения; `CLAUDE.md`, раздел «Тема оформления» — поправить фразу «личная настройка устройства» на «личная настройка пользователя: KV `access/<uid>.theme`, `localStorage` — кэш, чтобы не мигало при открытии».

Не трогать: палитры и правила тем, раздел настроек (только добавить вызов сохранения), `state:config`, «Сбросить настройки» (тему по-прежнему не трогает).

Проверить:
1. На телефоне выбрать «Светлая» → открыть приложение на компьютере в Telegram (или закрыть и открыть снова на другом устройстве) — светлая без ручного переключения; открытие без вспышки (локальный кэш сработал, потом подтвердилось с сервера).
2. Сменить на компьютере на «Тёмная» → на телефоне после перезапуска мини-приложения тёмная.
3. Включить «Как на телефоне» на одном устройстве → на другом тоже режим `auto` (тумблер включён), фактическая тема — по системе каждого устройства.
4. Пользователь без сохранённой темы (новый) — тёмная по умолчанию; после первого выбора тема появилась в его записи (`/diag` или `kv HGET access <uid>`).
5. Сервер недоступен при смене темы — тема на экране всё равно меняется, показывается `toast` «не удалось сохранить тему на сервере».
6. «Сделки» и «Расчёт» читают одно и то же значение; `Сбросить настройки` тему не трогает.
